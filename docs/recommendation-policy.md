# 主流车型池与推荐规则

## 车型池

配置位于 `apps/api/src/modules/vehicles/mainstream-vehicle-pool.ts`，当前版本 `2026-10-16.1`。这是一份版本化的中国乘用车车系编辑清单，并非实时销量或热度排行榜，尚未接入销量数据源。

- `PRIMARY`：优先推荐的主流车系。
- `SUPPLEMENTAL`：符合条件的主推车系不足时，用于补充比较的车系。
- `EXCLUDED`：未纳入前两档的车系，默认不参与测评推荐；车型详情仍然保留。

按车系维护，不能因为品牌知名就放行旗下全部车型。品牌、车系别名在解析前统一；同车系的不同动力版本可分别评分，最终最多推荐一个版本。数据库与飞书数据源都在同一推荐入口应用此政策。

截至 2026-10-16，本地 645 条活跃车型记录中，主推 185 条（126 个规范化车系）、补充 111 条（101 个车系）、排除 349 条（347 个车系）；主推池包括 22 条 10 万元以内的记录，覆盖 ICE、HEV、PHEV、EREV、EV。这里只统计当前数据源的记录和规范化车系，并非市场销量。

维护时先确认车系及别名，再调整 `primary` / `supplemental` 配置，并递增版本、更新日期与来源。如果之后接入销量数据，应记录统计月份、统计口径及原始来源，验证覆盖率后再调整分档，不能把导入顺序当作热度。

只读检查当前实际数据源：

```sh
pnpm --dir apps/api audit:recommendation-pool
```

## 筛选与排序

1. 先按明确动力许可和预算上限排除车型；有预算上限时价格缺失或无效也排除。没有任何兜底可以恢复这些车型。
2. 只保留主推或补充池内的车系。现有条件规则全部满足时视为严格匹配；有严格匹配时不混入规则未满足的结果。只有没有严格匹配时，才允许其他条件规则的兜底，并显示提示。
3. 先主推、后补充，同档按匹配分排序；同分按 slug 稳定排序。各动力统一参与排序，取消电车固定排在前面的偏置及电车/SUV加分。
4. 最多推荐 6 辆，每个规范化车系最多 1 辆，同品牌最多 2 辆。不为动力类别预留名额；去重或品牌限额导致主推不够时，才继续选择补充池。
5. 返回池版本、来源、日期、档位及选择说明，页面展示全部入选车型。不满足条件时允许少推或为空，给出空结果说明。

匹配评分保留现有画像、成本、用车条件及车辆核心维度，移除的 7% 车型类别加分并入核心向量匹配（30% → 37%）。此调整是可回归的规则校准，尚无线上点击/收藏/试驾反馈来证明转化提升。

人数参与画像评分，目前车型表没有座位数字段，尚不能保证“7 人需求一定匹配 7 座”。后续补齐座位数才能增加这一硬筛选。

## 验证与同步

典型画像回归覆盖低预算油车、低预算纯电、家庭混动备选、补能便利新能源、不限预算纯电，以及别名去重、品牌上限、主推补充顺序、预算/能源兜底边界。完成测评和再次读取结果都走同一筛选入口。

题库更新使用 `sync:questions`，不要运行会清空业务数据的 `db:seed`。选题规则、信息覆盖阈值和安全同步流程见 `docs/question-conditions.md`。
